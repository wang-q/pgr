# 基于 .pgi + PAF 的最大化共线性捕获命令（设计稿 + 计划，修订 v3）

> 2026-08-09 起草，同日修订 v2/v3。
>
> **目标（用户定稿）**：尽量捕获共线性的区域——从已有比对（PAF）出发，用 `.pgi`（排序
> syncmer 索引）找出 PAF 覆盖之外仍有同源/共线性信号的区域，尽量捕获高分歧/弱同源区。
>
> **修订 v3（用户纠正命令形态）**：不做"编排壳"。编排（`align pgi` / `fill` / `rest` /
> `chainnet`）在命令行就能手动完成，**不需要新命令**。要设计的是**数据级算法命令**：
>
> > 输入：`.pgi` 文件（每基因组排序 syncmer 索引）+ 排好的 PAF（已有比对）
> > 输出：捕获更多共线性后的 PAF / MAF
>
> 本命令只做"在 `.pgi` + PAF 之上的后续工作"，不负责上游建索引/比对。

## 0. 一句话

命令输入 N 个 `.pgi`（排序 syncmer 索引）+ 一个已排好的 PAF（锚点比对），通过 `.pgi` 的
跨基因组共享 syncmer 信号，找出 PAF 未覆盖但仍可能同源/共线的区域（高分歧、弱同源），
用 LASTZ（低敏感度）补比对并合并，输出捕获更多共线性后的 PAF。

```
pgr <synteny> <genome...> --pgi <pgi1,pgi2,...> --paf anchors.paf -o refined.paf
```

上游（建 `.pgi`、`align pgi`/`fill`/`rest` → PAF）由用户在命令行手动完成；本命令只消费
`.pgi` + PAF。

## 1. 定位与动机

### 1.1 为什么是"数据级算法命令"

- **编排不是增量**：`align pgi` → `fill`/`rest` → `chainnet` 都是现成命令，手动串联即可，
  一个 `pl` 编排壳没有新价值。
- **增量在算法**：真正新的是"**如何发现 PAF 覆盖之外的同源/共线性区**"。这正是 `.pgi`
  能提供的：跨基因组共享 syncmer 信号，即使差异过大没形成 PAF 命中，也留下了共线证据。
- **输入契约明确**：`.pgi`（信号）+ PAF（锚点），输出扩展后的 PAF。上游/下游都是 pgr
  生态，命令只做中间这一段。

### 1.2 覆盖阶梯（为什么需要本命令）

| 层 | 机制 | 捕获范围 | 上限 |
|---|---|---|---|
| pgi 锚点（→PSL→PAF） | k=40 syncmer 共享精确种子 | 低分歧保守区 | 漏高分歧区（MAF 89.3%） |
| `align fill`/`rest` | 锚点 gap / 补集 + LASTZ | 锚点间 / 锚点外中高分歧 | 仍漏差异过大、无共享种子区（MAF 89.99%） |
| **本命令** | **用 `.pgi` 共享 syncmer 信号定位 PAF 未覆盖的候选区，LASTZ 低敏感度补** | 尽量逼近 lastz-only（90.24%） | lastz 本身也有边界 |

> lastz-only MAF 90.237% vs pgi-only 89.297%（差 ~0.94 pp）——这 0.94 pp 是高分歧同源区，
> fill/rest 部分捕获、但**不能保证全捕获**。本命令用 `.pgi` 的共享 syncmer 信号把它们
> 尽量吃满。

## 2. 算法设计：基于 .pgi 信号的补全闭环（核心新增）

```
输入：
  - N 个 .pgi（排序 syncmer 索引，每基因组一个）
  - PAF（排好的锚点比对）

1. 跨基因组共享 syncmer 集
   对 N 个 .pgi 的排序 k-mer 键做多路归并 → 在 ≥2（或全部）基因组出现的 syncmer。
   对每个共享 syncmer 记录各基因组的 (contig, pos, strand)。
   → 精确替代 common Bloom filter，无假阳性；纯 .pgi 排序归并，O(总条目数)。

2. 锚点覆盖区
   读 PAF → 各基因组已覆盖区（runlist）。

3. 候选区定位（本命令核心）
   对每个基因组：找"有共享 syncmer 信号、但未被 PAF 覆盖"的区域：
   - 沿每 contig 的有序共享 syncmer（按 pos）滑窗，统计共享 syncmer 密度；
   - 密度 ≥ 阈值 且 与 PAF 覆盖无交 → 候选区（高分歧/弱同源共线性区）。
   → `.pgi` 提供了 PAF 之外的共线证据，这是 fill/rest 没有的信号。

4. 补比对
   提取候选区（2bit range，按 .pgi 位置），LASTZ（低敏感度）比对 → 新 PAF，
   坐标回移（psl lift 逻辑）。

5. 迭代（可选）
   合并新 + 旧 PAF 作为 C_{i}，重复 3-4（降低敏感度）直到收敛
   （覆盖增量 < 阈值 / 敏感度下限 / 轮数上限）。

6. 输出
   合并后的 PAF（或经 chainnet --syn → MAF）。
```

**降敏感度方向**：更小 `-k` / 更低 `--min-shared` / 更宽松 LASTZ 打分 / 增大滑窗。

**收敛准则**：覆盖不再增加、敏感度到下限（再降只出假阳性）、或轮数上限。

## 3. 目标与成功标准

- **目标 1（算法）**：实现"用 `.pgi` 共享 syncmer 信号定位 PAF 未覆盖候选区 → LASTZ 补"。
- **目标 2（迭代）**：迭代降敏感度直到收敛。
- **目标 3（验证）**：覆盖对照 lastz-only（上限）与 FastGA/ntSynt。
- **成功标准**：
  - 输入契约：`.pgi` + PAF，输出 PAF；上游/下游均可手动 CLI 完成；
  - 覆盖单调上升且逼近 lastz-only（如 ≥ 90.2%，差 < 0.1 pp）；
  - 敏感度下限控制假阳性（新增里低 identity 比例可控）；
  - 不引入新依赖；字节级一致性测试不受影响；
  - 迭代轮数/耗时可控。

## 4. 复用点清单（本命令消费的现成能力）

| 现有能力 | 复用处 |
|---|---|
| `pgr pgi build`（排序 syncmer 表） | `.pgi` 输入（用户在建） |
| `PgiQuery`（`entry_range`/`entry_kmer`/`entry_positions`） | 读共享 syncmer 的 (contig,pos,strand) |
| `.pgi` 排序特性 | 多路归并求跨基因组共享 syncmer |
| PAF 读取 / runlist / span_op | 读锚点、算覆盖区、求候选区 |
| `pgr 2bit range` | 提取候选区 |
| LASTZ 封装（`libs/lastz` + `align/common.rs`） | 补比对 + 坐标回移 |
| `pgr pl chainnet --syn`（手动） | 最终 MAF 口径（用户下游） |

### 5.1 阶段 0 结果（mg1655 × nissle1917，2026-08-09，`examples/synteny_poc.rs`）

**发现 1 — 共享 syncmer 信号几乎全在锚点覆盖内**：

| k | genome1 共享 syncmer 未覆盖位置 | genome2 未覆盖 |
|---|---:|---:|
| 40 | 92 (0.01%) | 84 (0.01%) |
| 24 | 698 (0.05%) | 330 (0.02%) |
| 20 | 1146 (0.08%) | 604 (0.04%) |
| 16 | 3166 (0.20%) | 3470 (0.21%) |

共享 syncmer（两基因组共有 k-mer）**99.8%+ 落在 PAF 已覆盖区**；即使 k 降到 16，未覆盖区里的共享
syncmer 仍仅 ~0.2%。原因：PAF 未覆盖的高分歧区里根本没有共享 k-mer（分歧太高留不下低 k 精确匹配）。

**发现 2 — 未覆盖区组成（genome1）**：

| 指标 | bp | 占基因组 |
|---|---:|---:|
| pgi 锚点覆盖 | 4,038,559 | 87.01% |
| lastz 覆盖（金标准） | 4,201,465 | 90.52% |
| pgi 未覆盖 | 603,093 | 12.99% |
| ├ 可捕获（未覆盖 ∩ lastz，高分歧共线性） | 162,956 | 3.51%（占未覆盖 27%） |
| └ 株特异/无直系同源（未覆盖 − lastz） | 440,137 | 9.48%（占未覆盖 73%） |

**阶段 0 定论（决策门）**：`.pgi` 共享 syncmer 信号对"捕获 PAF 之外共线性"**无杠杆**——
未覆盖区 73% 无直系同源，可捕获的高分歧共线性区（3.51%）里几乎没有共享 syncmer。
"最大化共线性捕获"实际是 **LASTZ（fill/rest）** 的事，且 fill/rest 到 lastz 差距本就小
（MAF 89.99% vs 90.24%）。**放弃"用 .pgi 共享 syncmer 定位未覆盖区"的方向**。

```
阶段 1（重定向，待定）：若仍要"最大化共线性捕获"
  ├─ 主战场是 LASTZ：fill/rest 已到 89.99%，余 ~0.25pp 靠 LASTZ 打分/参数微调
  ├─ 可选增强：跨 N 基因组保守块（多路共享 syncmer 求核心区，ntSynt 语义）
  └─ 决策门：用户确认方向后立项
```

> 阶段 0 之后，原计划 §2 的"共享 syncmer 信号定位未覆盖区"核心机制已证伪；后续无论走哪条，
> 都不再以它为支柱。

## 6. 开放问题

1. **命令形态与归属**（v3 修正后重新开放）：本命令是数据级算法命令（`.pgi` + PAF → PAF），
   **不是 `pl` 编排壳**。归属候选：
   - `pgr align synteny`（产出比对，与 pgi/fill/rest/lastz 同族）；
   - 顶层 `pgr synteny`（独立分析命令）；
   - 归入 `pgr paf`（消费 PAF）？
   ——待定，倾向 `align` 族或独立顶层。
2. **候选区定位的阈值**：共享 syncmer 密度阈值、滑窗大小——决定"有信号未覆盖区"的召回与
   假阳性，需阶段 0 实测。（注：阶段 0 已证伪信号，此阈值问题随之失效。）
3. **"共享"的基因组数**：共享 syncmer 定义为"≥2 基因组"还是"全部"？影响对高分歧的容忍度。
4. **收敛与假阳性**：敏感度下限如何定，避免为覆盖率引入大量低 identity 假阳性。
5. **覆盖口径**：以 MAF（`chainnet --syn`）为最终口径（沿用 `pgi-lastz-hybrid.md` 结论）。
6. **是否需要 LASTZ**：候选区补比对用 LASTZ（外部依赖）还是 pgi 内部可做？——先沿用 LASTZ
   （与 fill/rest 一致）。

## 7. 结论（修订 v3）

- **不做编排壳**：`align pgi`/`fill`/`rest`/`chainnet` 手动 CLI 即可，无新命令价值。
- **命令 = 数据级算法**：输入 `.pgi` + 排好的 PAF，输出捕获更多共线性后的 PAF；
  核心是用 `.pgi` 的跨基因组共享 syncmer 信号定位 PAF 未覆盖的同源/共线区（高分歧、弱同源），
  LASTZ 低敏感度补比对。
- **增量明确**：不是编排，而是"候选区定位 + 补比对"算法（`libs/` 放算法，`cmd_` 薄壳）。
- **第一步（阶段 0）**：PoC 验证"共享 syncmer 信号能否定位 PAF 未覆盖的共线性区"，再定阶段 1。
  ——**阶段 0 已执行且证伪该信号**（§5.1），方向重定向为 LASTZ 或放弃。
